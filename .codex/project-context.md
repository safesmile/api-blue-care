Estado vigente de identidad/autorización: ver docs/identity-authorization.md. Los usuarios reciben nombres y apellidos canónicos, name derivado, políticas en casos de uso y roles personalizados administrables. AuthGuard valida únicamente sesión y permisos de ruta. Al construirlos, autorizar por expediente antes de firmar un enlace y validar contenido real del archivo (el adaptador actual solo limita MIME declarado y tamaño).

La API de roles y la primera versión de notificaciones durables están implementadas; la interfaz frontend de roles sigue pendiente. Expediente clínico completo, odontograma y agenda clínica están fuera de Entrega 1. Kraken tiene más funciones que las incluidas aquí; no asumir paridad completa. Los correos con enlaces de invitación, activación y recuperación conservan envío inmediato por SMTP y requieren reintentar la solicitud si falla el envío. Los avisos generales y posteriores de seguridad usan el outbox durable. Los enlaces de acciones esperan sus pantallas del frontend y usan token en query string, según README y m01-authentication.md.

Limitador por proceso: para múltiples instancias usar almacenamiento compartido y configurar proxy de confianza con topología conocida antes de basarse en IP reenviada.

Lee README.md para arranque y comandos. No crear una cuenta de administrador automáticamente ni introducir contraseñas fijas.
